# Ephemeris source evaluation

## Decision

Use `astronomy-engine` for the high-accuracy ephemeris adapter when Task 5 adds a dependency.

Rationale:

- It is the best match for the provider contract: topocentric Sun/Moon equatorial positions, horizontal conversion for an Earth observer, geocentric vectors for the orrery, and phase/illumination primitives are all first-class documented APIs.
- It is browser-compatible and ships generated TypeScript/JavaScript plus browser bundles, so it fits the current Vite/static deployment model.
- Its built-in `SearchRiseSet` deliberately includes atmospheric refraction and apparent body radius, so the app should **not** use that routine for displayed rise/set. Displayed rise/set remains the app's own geometric horizon crossing: no refraction, no apparent radius, no terrain.
- The existing URL and time contract stay unchanged: `date` and `time` continue to mean mean solar time at the selected longitude, UTC remains a read-only reference, and the schematic orrery remains schematic. The ephemeris source supplies observed/topocentric Sun and Moon state and geocentric directions; it does not change the page shape, controls, URL, or fictional distances/sizes.
- Use JPL Horizons only for offline/manual reference fixtures and checks. Do not call Horizons from browser runtime.

## Implementation notes for Task 5

- Add only `astronomy-engine` when implementing the ephemeris adapter; this task intentionally adds no dependency.
- For observed Sun/Moon altitude and azimuth, compute topocentric equatorial coordinates with an `Observer`, then call horizontal conversion with refraction disabled. In TypeScript, do this by omitting the optional refraction argument or passing `undefined`; do not pass `null` if the shipped declaration rejects it.
- For rise/set, continue the app's geometric altitude crossing search. Do not delegate displayed rise/set to a library routine that includes refraction or apparent radius.
- For the schematic orrery, use geocentric directions/vectors from the same source, but keep all distances, radii, and drawing scales schematic.
- Use saved JPL Horizons/Astronomy Engine fixtures for tests. No browser-runtime Horizons calls.
